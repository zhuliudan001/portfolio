# 首页巡游小鲨鱼 —— 设计规格

日期：2026-10-14　状态：待评审
关联：`2026-10-12-portfolio-restructure-design.md`（本文件修订其 §3「产物零 JavaScript」与 §11 部分断言）

## 1. 目标与非目标

**目标**：首页背景目前只有纸白底 + 虚线分隔，观感单调。加一只与头像同源的线条小鲨鱼，在正文背后的低对比层里缓慢巡游、到边掉头、遇指针受惊游走。

**次级目标**：这块动效同时是技术栈里「canvas 绘图与导出」那条主张的活证据 —— 站点自我介绍说会 canvas，首页就真的跑着一段手写 canvas 动画。

**非目标**：不做详情页动效、不做多条鲨鱼、不做气泡粒子与音效、不做滚动视差、不做暂停按钮、不做鼠标跟随（鲨鱼是"怕人"不是"亲人"）。

## 2. 契约变更：从「零 JavaScript」到「零运行时依赖 + 一处内联动效」

原契约：11 份产物全部无 JS。改为三条更精确的锁，一条比一条严：

1. **零网络依赖不变**。全站产物仍禁 `fetch(` / `XMLHttpRequest` / 任何 `http(s)://` 外链（现有断言原样保留）。`file://` 双击可开这条不动。
2. **JS 只允许出现在 `index.html`，且恰好一个内联 `<script>`**。断言从"没有 `<script`"改为：`<script` 出现次数 === 1；脚本体内无 `src=`、无 `eval`、无 `document.write`、无 `fetch`。
3. **10 份 `case/*.html` 仍然零 JS**。这条断言一字不改，防止以后把动效铺到长文阅读页。

**代价如实记录**：README 首句、CLAUDE.md、原规格 §3 与 §11 里"产物零 JavaScript"这个卖点改写为"零运行时依赖"。丢掉的是"纯静态无脚本"这层态度，换回的是首页动效能力与一条可自证的 canvas 主张。

## 3. 架构与文件边界

最容易踩的坑是"测的是一套、上线的是另一套"。运动逻辑写成纯函数模块，Node 测它、浏览器跑同一份源码。

| 文件 | 职责 | 变化 |
|---|---|---|
| `scripts/shark-motion.js` | 鲨鱼怎么动（`step`）、长什么样（`render`）、全部运动常量 | 新增 |
| `scripts/template.js` | `sharkLayer()` 产出 `<canvas>` + 那段胶水脚本；`layout()` 决定是否注入 | 改 |
| `scripts/build.js` | 读 `shark-motion.js` 源码内联进首页；三道契约锁的断言 | 改 |
| `css/style.css` | `.shark` 定位层级、reduced-motion 时隐藏 | 改 |
| `tests/shark.test.js` | 运动与配色的性质断言 | 新增 |

**一份源码两处消费的机制**：`shark-motion.js` 是 CommonJS 文件，但**禁止 `require()` 任何东西**（构建时断言这条，否则内联进去就是坏代码），并且**只在文件末尾留一行** `module.exports = { step, render, ... };`。`build.js` 用固定正则剥掉这最后一行，把剩下的源码原样塞进 `<script>` 的 IIFE 里 —— 剥的不是正则匹配到的任意片段，就是这一行，多一处 `module.exports` 会让构建报错而不是静默少代码。浏览器与测试执行的是同一份函数体。

内联的是静态文本，所以现有的"两次构建逐字节一致"聚合哈希锁自动覆盖它，不需要新机制。

## 4. 运动模型

状态：`{ x, y, heading, speed, tailPhase, turnBias, turnTimer, startle }`。单位：CSS 逻辑像素、弧度、秒。

`step(state, viewport, dt, rand, pointer) -> state` 是纯函数：不读 `Date`/`performance`/`window`，`dt` 与随机源由调用方注入，`pointer` 为 `{x, y}` 或 `null`。

每步语义：

1. `dt` 钳制到 `min(dt, 0.05)` —— 切走标签页再回来时不让它一次跳一大步。
2. `turnTimer -= dt`；归零时重新 `turnBias = (rand()*2-1) * TURN_RANGE`，并重置 `turnTimer` 为 2–4 秒（由 `rand` 决定）。**这是"巡游"而非"抖动"的关键**：方向每隔几秒才慢慢换一次意图。
3. 求期望方向：巡游时朝 `heading + turnBias`（**2026-10-15 修订，见文末 R1**：字面写法是跟随式目标，实测每帧满舵画圆，实现改为「消耗额度」）；有指针在回避半径内时朝远离指针的方向（§5）。两者按惊扰程度线性混合。
4. `heading` 以不超过 `TURN_MAX` rad/s 的角速度向期望方向转（取最短弧）。
5. `speed` 向目标速度靠拢（目标 = 巡游基准或惊扰加速），同样限速。
6. `x += cos(heading)*speed*dt`，`y += sin(heading)*speed*dt`。
7. 边界：预测下一步会越出 `[margin, size - margin]` 时，把期望方向改为指向视口内侧（向心掉头），**不做硬反弹**；若因 resize 已经越界，直接 clamp 位置并置一次向心掉头。
8. `tailPhase += dt * 摆速(speed)`，尾鳍偏角 = `sin(tailPhase) * TAIL_SWING`。

### 常量表（写在 `shark-motion.js` 顶部，测试直接引用同一份）

| 名称 | 值 | 说明 |
|---|---|---|
| `bodyLength(vw)` | `clamp(vw * 0.09, 56, 96)` | 身长随视口，900px 宽时 81px |
| `baseSpeed(L)` | `clamp(L * 0.8, 45, 75)` px/s | 巡游基准速度 |
| 巡游速度区间 | `base × [0.8, 1.6]` | |
| `TURN_RANGE` | 0.6 rad | 一次意图要转过的**总角度**（原写 `rad/s` 是笔误；R1 之后它真的是「转向额度」，单位也才立得住） |
| `TURN_MAX` | 1.2 rad/s | 实际转向角速度上限 |
| `turnTimer` | 2–4 s | 重取 turnBias 的周期 |
| `TAIL_SWING` | 14° | 尾鳍摆幅 |
| 摆速 | `clamp(6 + 8*(speed/base - 1), 4, 16)` rad/s | 游得快摆得快 |
| `margin` | `0.6 * L` | 距边多远开始掉头 |
| `AVOID_R` | `1.6 * L` | 指针回避半径 |
| `startleSpeed` | `min(base * 3.2, 220)` px/s | 受惊速度上限（防弹射感） |
| 惊扰恢复 | 1.5 s 线性衰减 | 指针离开半径后回到巡游 |
| `clickPulse` | 0.6 s，速度 ×1.5、摆速 ×2，线性衰减 | 点击脉冲 |

浏览器端随机源：`mulberry32` 以**按天稳定**的 `Math.floor(Date.now() / 864e5)` 播种（R4 前是裸 `Date.now()`，于是每刷一次页面鲨鱼就换一个起点，截图核对与观感调试全被打断）。隔天换一条路线；测试端注入固定 seed 的 PRNG，因此可复现。

## 5. 指针互动（怕人模型）

- 指针进入 `AVOID_R`：期望方向叠加"远离指针"的分量，权重 `w = 1 - d / AVOID_R`（越近越强，钳到 [0,1]）；`speed` 目标升到 `startleSpeed`。
- 指针离开 `AVOID_R`：`w` 在 1.5 秒内线性衰减到 0，回到巡游。
- 点击（`pointerdown`）：触发一次 `clickPulse`。不产生粒子、不改变位置。
- 触屏没有 hover：`pointerdown` 的坐标同时充当一次性惊扰点，不做持续跟随。
- 只读指针坐标作为下一帧入参；不记录轨迹、不写 storage、不发任何请求。

**为什么选"怕人"而不是"跟随"**：回避机制顺手解决了可读性问题 —— 鼠标停在哪，那一块就保证没有鲨鱼。跟随会让鲨鱼追着光标钻进正文，把 §6 用低对比度压下去的干扰又请回来。

## 6. 画法与配色

**程序化矢量，不用位图。** 位图有两个死结：AI 生成的图没有干净透明底；而头像那张是"纸色方块里的一颗头"，游起来像一块瓷砖在飘。

`render(ctx, state, view)` 用路径画，造型呼应头像那只线条鲨。**（2026-10-15 两轮形状改版，见文末 R3/R4）** 现为：鱼雷形身体（上下各两段三次贝塞尔，尾柄半宽 6.5）+ 背鳍（底边两端采自背线、前缘直、后缘内凹）+ 异形尾（上叶是下叶的 1.8 倍）+ 两道鳃裂 + 深色月牙口腔内收两颗牙 + 实心墨眼带一点高光 + 描边身体 3、鳃裂 2.4。`cos(heading) < 0`（朝左）时水平镜像，保证肚皮永远朝下、不会上下颠倒。

改版前是「对称椭圆身 + 头顶一块小三角 + 上下同形的尾 + 一排六颗牙画在身体中段」，放大到 320 单位看四处硬伤：牙不在吻部而在肚子上、身体没有鱼雷形、尾鳍丢了鲨鱼最认得出的特征、背鳍底边不贴背线像扣了顶帽子。

配色不走"把墨色调透明"那条路 —— 降透明度会连带吃掉正文对比度。改成给它一套本来就低对比的颜色：

| | 浅色态 | 深色态 |
|---|---|---|
| 身体填充 `fill` | `#d9d9d9` | `#2d2d2d` |
| 描边 `line` | `#b3b3b3` | `#4a4a4a` |
| 肚皮 `belly` | `#f2f2f2` | `#1a1a1a` |
| 眼白/牙 `eye` | `#fafafa` | `#1a1a1a` |
| 眼睛与口腔 `ink` | `#8a8a8a` | `#8f8f8f` |

`ink` 是形状改版新增的一档，替掉原 `pupil`：旧值浅色 `#b5b5b5` 对白底只有 1.86、深色 `#4a4a4a` 压在填充 `#2d2d2d` 上只有 1.53，在 56–96px 的实际尺寸下眼睛等于没有，「可爱」立不住。

**对比度约束按角色分三层**（复用现有 `contrast()` 断言，下表数字已用该函数实测）：

| 角色 | 约束 | 为什么 | 实测 |
|---|---|---|---|
| 描边（剪影） | 与页面底色比 **1.5 – 2.4 : 1** | 它决定"看不看得见这只鲨鱼"。低于 1.5 剪影就化了（用户明确否掉过水印级）；上界从 1.9 放宽到 2.4 是形状改版的实测需要 —— 新造型把识别度全押在轮廓上，1.7 档的描边在 56–96px 实物尺寸下几乎看不见 | 浅 2.10 / 深 2.18 |
| 填充（正文会从它上面经过） | 与页面底色比 ≤ **1.9**，且正文压在其上 ≥ **7 : 1** | 它决定"抢不抢字"。AA 只要 4.5，这里留足余量，因为鲨鱼会游到段落底下 | 浅 1.41、正文 13.38 / 深 1.40、正文 11.66 |
| 内部细节（肚皮、眼白、眼睛与口腔） | 与填充比 ≥ **1.2** | 只是层次，不承担识别 | 浅 1.26/1.35/2.45 / 深 1.26/1.26/4.26 |

这条分层是实测逼出来的：填充只比纸底暗 1.41，内部细节再差 1.26 —— 意味着**这只鲨鱼的识别度必须全靠剪影**（背鳍 + 异形尾 + 吻部嘴线的轮廓），不能指望明暗塑形。画的时候轮廓线要够"狠"，细节当点缀。若 §9 的截图显示它糊成一团灰，解法是加大描边与底色的比（往 2.4 顶）并强化轮廓形状，而不是整体调透明。

主题切换由胶水层用 `matchMedia('(prefers-color-scheme: dark)')` 选色表，不读 CSS 变量（canvas 拿计算样式要逐帧查询，不值）。

## 7. 无障碍与性能

- `prefers-reduced-motion: reduce` → 不启动 rAF，且 CSS 直接把 `.shark` 设为 `display: none`。不画"一条静止的鲨鱼" —— 一个本该动的东西停在那里反而更怪。
- canvas 元素 `aria-hidden="true"`、`pointer-events: none`，纯装饰，不进无障碍树。
- `visibilitychange` 隐藏时暂停循环，回来续上。
- DPR 感知：画布尺寸 = 逻辑尺寸 × `min(devicePixelRatio, 2)`，上限 2 防高 DPI 手机过度采样。
- `resize` 重算尺寸与身长，并把位置 clamp 回新视口。
- 层级：`.shark { position: fixed; inset: 0; z-index: 0 }`，同时给 `.masthead, main { position: relative; z-index: 1 }` —— 定位元素默认会盖在普通流内容之上，这一条不给就会糊在文字上。

## 12. 修订（2026-10-15，Task 5 视觉核验后）

三条都是「跑起来看」才暴露的，纸面评审与既有断言都拦不住。数字全部由 `.superpowers/sdd/2026-10-14-swimming-shark/` 里登记的探针脚本复算得出（`probe-360.js` 出贴墙率与满舵率、`trace.js` 出轨迹留痕、`verify-final-claims.js` 出变异回归）；截图与临时页所在的 `portfolio/.probe-shark/` 是收尾即删的暂存目录，不在仓库里。

### R1 巡游改成「消耗转向额度」

§4 第 3 条字面写法 `want = angleDelta(heading + turnBias, heading)` 是**跟随式目标**：目标跟着当前朝向一起走，`want` 恒等于 `turnBias`，`want/dt ≈ 36 rad/s` 每帧都被钳到 `TURN_MAX`。后果是它永远满舵 —— 实测满舵帧 **100.00%**（四档视口全一样）、角速度恒为 68.8°/s、转弯半径恒等于身长的 **0.75 倍**，轨迹留痕是一串闭合正圆。`TURN_RANGE` 因此只决定了「往哪边打转」，完全没决定「转多少」（`|turnBias| > TURN_MAX·dt` 的概率 96.7%，额度大小被钳掉了）。这与 §4 第 2 条自己声明的「这是巡游而非抖动的关键」正相反。

实现改为把 `turnBias` 当**剩余待转角度**：`want = turnBias`，本帧实转 `turned` 后 `turnBias -= turned`，且只在巡游意图未被逃离/向心接管时消耗（扰动过后这次转向还会继续）。`|turnBias| < turnCap·s` 时 `turned` 恰好等于 `turnBias`，额度归零而过冲不了。

修后实测（登记的 `probe-360.js` 跑 120 秒档）：满舵帧 **24.78–31.79%**（60 秒档是 22.7–29.8%，两档都记，别只引一个），平均角速度 17.2–22.0°/s，360px 下换向从 696 次/分降到 151 次/分，轨迹变成「长直线滑行 + 边界圆弧掉头」。钉它的断言是 `巡游意图转完就收敛`（满舵不过半、最长直游段 ≥60 帧、单次意图转角 ≤ `WANDER_RANGE`）与 `残留转向额度`（接管帧不动额度、巡游帧按 `TURN_MAX×dt` 扣减、1 秒内归零），证伪：还原跟随式 → 红 `满舵帧占 100.0%`；无条件消耗 / 接管即作废 两种改法 → 都被 `残留转向额度` 咬住。

> 两处数字在初稿里写错了，实测更正：① 上面那句「每帧满舵」才是缺陷本体，转弯半径 `speed/TURN_MAX` 本身随速度游走，实测是身长的 **0.53–1.07 倍**（不是「恒为 0.75 倍」，且修复前后同分布，因为速度逻辑没动）；② 副作用那条「360px 贴墙 9.46% → 12.63%」是**单个 seed 的尾值** —— 22 个 seed × 120 秒重测：360px 中位 **5.79%**、区间 1.08–20.10%，900px 中位 0%、最大 5.75%。**登记口径现在是可执行的**：`node .superpowers/sdd/2026-10-14-swimming-shark/probe-360.js` 末尾一节直接打印（seed 集 `1000 + k*7919, k=0..21`，每段 120 秒，无指针），并附登记 seed `20261014` 的单跑值（360px = 12.63%，900px = 0%）——上一版终审判定这些数字「按登记口径复算不出」，根因是口径只写在散文里没有脚本承载；现在脚本即口径，改判据必须同时改脚本。而且该判据量的是「中心到 margin 盒」的距离，中心到真实屏幕边缘全程 ≥ 39.2px = 0.70 倍身长。真机制也不是「直游段变长的必然结果」，而是 §4 第 7 条的前瞻判据只看「正在朝外的那两侧」，**切向朝向时它不触发**，于是它贴着侧壁直线穿过。取舍不变（不加侧向规则 —— 实测砍掉残留额度反而升到 12.38%），但理由按上面这条写。

### R2 描边带宽上界 1.9 → 2.4

新造型把识别度全押在轮廓上，`#c4c4c4`（1.74）在 56–96px 实物尺寸下几乎看不见轮廓。浅色描边提到 `#b3b3b3`（2.10）、深色 `#3a3a3a`→`#4a4a4a`（2.18）。带宽上界随之放宽到 2.4。

曾想再加一条 `正文/描边 ≥ 7` 兜住「轮廓不与文字抢层级」，实测算下来它是**死断言**：浅色板在带宽上界 2.4 处该比值是 7.87，永远不可能先违反它；深色板也只有 2.34–2.4 这 0.06 的窄窗能触发。所以撤掉，让带宽做唯一的上界，而不是摆一条咬不到人的锁。

同一把尺子回头量既有那条 `正文/填充 ≥ 7`：**固定 text、穷举 fill 的合法灰阶**（浅 68 个 / 深 66 个满足 `≤ 1.9`），比值最小是 9.94 / 8.64 —— 也就是说在 fill 这根轴上它同样被 `fill ≤ 1.9` 蕴含，不是第二道闸。但它**不是死断言**：换到 text 轴上它会咬 —— text 亮过 `#444`（浅色板）或暗过 `#b8b8`（深色板）就触发。结论是「留着，但注释必须写清它管哪根轴」，测试里的注释已按此更正（初稿注释引用了已撤掉的 `text/line`，属于假注释）。
