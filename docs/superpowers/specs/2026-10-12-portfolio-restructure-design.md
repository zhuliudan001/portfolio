# portfolio 重构设计：Three.js 星系 → 编辑式静态站

日期：2026-10-12 · 范围：`portfolio/`（写入仅限本目录）· 状态：待用户复核

## 1. 目标

把 `portfolio/` 从 Three.js 沉浸式「代码星系」重构为参考 https://preetsuthar.me 的编辑式单栏静态作品集：内容策展自上级仓库的兄弟小程序项目，构建期生成 HTML，产物零 JS。

## 2. 非目标

- 不改动 `portfolio/` 之外任何文件（只读扫描兄弟目录是既有设计例外，写入禁止）
- 不动 `portfolio/.kilo/`（Kilo 工具的 worktree 副本，非本项目产物）
- 不做图片/截图展示（仓库内无可用项目截图资源，`assets/` 为空）
- 不做主题切换开关、不做运行时筛选交互（参考站即零 JS）

## 3. 已确认决策

| 议题 | 结论 |
|---|---|
| 整体形态 | 纯编辑式单栏 + 精选项目详情页 |
| 3D 星系 | 彻底删除，无需 git 检查点（用户已授权「可随意删除」） |
| 渲染方式 | 构建期生成静态 HTML（`node scripts/build.js`） |
| 项目策展 | 精选 10 条（有详情页）+ Archive 归档其余 |
| 个人身份信息 | 派生统计只写可核实事实；未提供的个人字段用假数据占位，集中在一个文件内便于替换 |
| 视觉基准 | preetsuthar.me 的 `style.css`（已抓取全文，约 5.8KB） |

占位假数据的标记约定：`content/site.js` 中每个占位字段附 `占位: true` 标记，页面上渲染为正常外观的假值（如 `某科技公司`、`your-email@example.com`），`build.js` 汇总打印「N 个字段待替换」清单（仅告警，不失败）。除 `site.js` 外任何文件不得出现个人身份假数据。

## 4. 架构与文件布局

```
portfolio/
├── content/site.js         个人信息假数据占位（姓名/定位/邮箱/电话/微信/GitHub/经历）—— 全站点唯一需替换处
├── content/featured.js     精选 10 条策展数据（slug/monogram/accent/一句话/要点）
├── scripts/scan.js         重写：只读扫描兄弟项目 → data/projects.json
├── scripts/curate.js       入选/去重/分组规则 → featured[] + archive[]
├── scripts/build.js        事实 + 内容 → index.html + case/*.html（含断言）
├── css/style.css           设计系统（覆盖旧孤儿文件）
├── data/projects.json      生成物：全量项目事实
├── index.html              生成物
├── case/<slug>.html        生成物：10 个详情页
├── README.md               重写
└── CLAUDE.md               重写（架构、陷阱、命令）
```

数据流：`scan.js` →（只读）兄弟项目 `manifest.json`/`pages.json`/`app.json`/源码探针 → `data/projects.json` → `curate.js` 切 `featured[]`/`archive[]` → `build.js` 套模板 → HTML。

生成物顶部注释 `<!-- GENERATED BY scripts/build.js — 请勿手改 -->`；手写内容只存在于 `content/`。所有产物 `file://` 双击可读。

## 追加（2026-10-14）：品牌标记

§8 原先把 `.avatar` 规则「保留供日后填图」，§9 记「无头像资源 → 不渲染」。现已落地为**鲨影侧视标记**：`img/avatar.svg`（轮廓 + 眼）用于 masthead，`img/favicon.svg`（同一轮廓的减法形，连眼也去掉）用于标签页。

过程与取舍（都是渲染实测得出的，不是审美偏好）：第一版做的是「方括弧 + 2×2 模块格」的抽象记号，用户判定效果不好，换成鲨鱼；加鳃缝的第二版在 48px 实际尺寸下与身体糊成灰带，遂只留轮廓——鲨鱼的辨识靠背鳍与不对称尾鳍，不靠内部细节。另两条：48 形直接缩到 16px 会糊（实心部退成中灰），所以小形单独出一档；眼睛贴着轮廓边线会被读成「吻部缺了一块」，必须整体落在体内。

图形为纯几何填充（无 `<text>`、轮廓不用描边），靠 SVG 自带 `prefers-color-scheme` 随系统反相，已在强制深色下实测生效（方块转纸色、鲨影转墨色）。`SITE.avatar` 指向的文件不存在时 `build.js` 直接断言失败。姓名等身份字段仍是占位符，因此刻意**不用** AI 人像：一张假脸会破坏整站「每条都可核实」的纪律。

## 追加（2026-10-14·二）：品牌标记改为蓝白鲨鱼头位图

用户连续否掉了方括号记号与单色鲨影，最终定为「蓝白配色、可爱、只画头」。这一版是 AI 生成的位图（母本 `img/avatar-source.png`，1024px，不被任何页面引用），`img/avatar.svg`、`img/favicon.svg` 已删除，改由 `scripts/export-avatar.ps1` 从母本居中裁方导出两档：`img/avatar.png` 256px（页面按 48px 显示）、`img/favicon.png` 32px。

随之作废的约束：「浅色态必须写成呈现属性」只服务于 SVG —— 位图把颜色烤死在像素里，不执行 CSS 的渲染器也不会变一团黑；`<style>` 里的 `prefers-color-scheme` 同理失效，浅色底 `#eaf2fb` 在深色页面上就是一块亮tile（已实测，观感可接受，不做深色变体）。`content.test.js` 那条呈现属性断言改写为按 PNG 签名 + IHDR 宽高核对，尺寸与用途（48 显示 / 标签页）绑在一起。

仍然成立的一条：不用 AI **人像**。身份字段是占位假数据，一张假脸会破坏整站「每条都可核实」的纪律；非写实的动物标记不声称任何事实。
